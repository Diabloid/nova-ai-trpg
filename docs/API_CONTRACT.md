**Версія контракту:** 1.1.0 (Уточнено структури предметів та здібностей)  
**Статус:** Обов'язковий до дотримання чатами **Backend** та **Client**.

## 1. Архітектурне правило ігрового циклу (Суворо послідовний пайплайн)

Аналізатор стану (State Analyzer) **НЕ МОЖЕ** запускатися паралельно з Оповідачем (Game Master/Narrator).  
Він працює строго за наслідками того, що сталося в художній сцені.

```
       [ Гравець ]
            │
            │  1. Відправляє ввід (текст + інтенси)
            ▼
     [ Оповідач (GM) ]
            │  - Зчитує поточний стан + історію + селективний лор
            │  - Описує реакцію світу та NPC (Стрімінг або повний текст)
            ▼
     [ Аналізатор стану ]
            │  - Отримує: дії гравця (action/speech) + згенерований текст Оповідача
            │  - Визначає дельту стану (травми, зміни інвентарю, переміщення)
            ▼
     [ Менеджер стану ]
            │  - Валідує дельту
            │  - Оновлює savegame
            ▼
     [ Клієнт C# ]
            - Оновлює панель персонажа та інвентар
```

## 2. Моделі даних (DTO / Schemas)

### 2.1. Токенізація намірів (Intent Tokens)
Клієнт аналізує текст гравця за синтаксисом:
- `**дія**` ➔ `"action"`
- `- репліка` ➔ `"speech"`
- `"думка"` ➔ `"thought"` (ігнорується аналізатором)
- `(поза грою)` ➔ `"ooc"` (ігнорується аналізатором)

```json
{
  "type": "action | speech | thought | ooc",
  "content": "текст наміру"
}
```

### 2.2. Запит дії гравця (`POST /api/v1/action`)
```json
{
  "raw_text": "Дістаю ключ із рюкзака та відмикаю старі двері",
  "intents": [
    {
      "type": "action",
      "content": "Дістаю ключ із рюкзака та відмикаю старі двері"
    }
  ],
  "session_id": "default"
}
```

### 2.3. Повна модель стану гравця (`PlayerState`)
*Увага: предмети, травми та здібності є повноцінними об'єктами з описом, а не простими рядками!*

## 3. Специфікація API ендпоінтів

| Метод | URL | Опис | Request Body | Response Body |
| :--- | :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/action` | Відправка кроку гравця, виконання повного пайплайну | `ActionRequest` | `ActionResponse` |
| `GET` | `/api/v1/state` | Отримання поточного повного стану | `?session_id=default` | `PlayerState` |
| `POST` | `/api/v1/action/stream` | SSE потік генерації розповіді з фінальним JSON стану | `ActionRequest` | `text/event-stream` |
| `GET` | `/api/v1/sessions` | Список доступних збережень | Відсутній | `List<SessionInfo>` |

## 4. Правила змін та узгодження
1. Жодна зі сторін (Backend чи Client) не має права змінювати імена або типи полів у DTO в односторонньому порядку.
2. Будь-яке розширення DTO фіксується у цьому файлі через pull request або затвердження Архітектором.
3. Усі ключі в JSON використовують формат `snake_case`. Клієнт на C# мапить їх у `PascalCase` через `[JsonProperty("...")]`.
