## 1. Архітектурне розділення: LLM Context (`history.json`) vs Повний чат (`chat_log.json`)

Файл `history.json` **НЕ ПОВИНЕН** використовуватися для виведення всього чату гравцю. Він призначений виключно як ковзний контекстний буфер для нейромережі.

### Необхідне розділення:
1. **`history.json` (Контекст LLM):**
   - Містить лише `summary` (стислий виклад минулих подій від літописця) та `recent_messages` (останні N реплік).
   - Підлягає постійній компресії та очищенню, щоб не перевищувати ліміти токенів.
   - Клієнту для відображення чату **не передається**.
2. **`chat_log.json` (Повний журнал чату для гравця):**
   - Зберігається окремо у `data/saves/{campaign_id}/chat_log.json`.
   - Зберігає **абсолютно всі повідомлення від самого початку кампанії** (вступний пост, дії/репліки гравця, художні описи Оповідача, системні алерти).
   - **Ніколи не скорочується, не стискається і не обрізається нейронкою.**
   - Саме з цього файлу ендпоінт `GET /api/v1/campaigns/{campaign_id}/history` віддає повну історію для UI клієнта (як у Telegram).
