**Дата аудиту:** Жовтень 2026  
**Стек:** Python 3.13, FastAPI, Uvicorn, Pydantic v2, AsyncOpenAI SDK.  
**Директорія:** `Backend_Python/`

## 1. Стан структури та зв'язності (Coupling & Cohesion)

### 1.1. Виявлені архітектурні дефекти
1. **Low Cohesion у `core/llm_manager.py` (Клас `LLMController`):**
   - Перевантажений відповідальностями: збереження історії, виклик fallback-провайдерів, читання промптів, читання 43 файлів лору, санітизація тексту, парсинг JSON Аналізатора, компресія історії.
   - Порушення SRP (Single Responsibility Principle).
2. **Tight Coupling та відсутність DI:**
   - `main.py` інстанціює `llm_controller` та `game_state` як глобальні змінні.
   - Відсутнє поняття ігрових сесій (`session_id`). Усі запити пишуть в один монолітний `savegame.json` та `history.json`.
3. **Синхронне блокуюче I/O в async функціях:**
   - Виклики `open()` для 43 файлів лору та читання промптів блокують event loop `asyncio`.
4. **Антипатерн у FastAPI сигнатурі:**
   - `async def process_action(data: dict)` замість типізованої Pydantic-моделі `ActionRequest`. Знищує автогенерацію Swagger (`/docs`) та строгу валідацію.

## 2. Пайплайн генерації: Гравець ➔ Оповідач ➔ Аналізатор ➔ Стан

```
[Запит гравця: raw_text + intents]
               │
               ▼
   [ 1. Читання стану: GameState ]
               │
               ▼
   [ 2. Оповідач: LLMController.generate_story ]
         - 43 файли лору (253 КБ) + summary + narrator_system.txt
         - Температура: 0.7
         - Запис у recent_messages та history.json
               │
               ▼
   [ 3. Аналізатор: LLMController.generate_state_json ]
         - Фільтр: Тільки action + speech (думки й OOC відкидаються)
         - context_str + state_system.txt
         - Температура: 0.0
         - Вирізання JSON підрядка [start:end+1]
               │
               ▼
   [ 4. Менеджер стану: GameState.update_from_llm ]
         - Валідація через Pydantic StateDelta
         - Мутація savegame.json
```

### Критичні вузькі місця:
1. **Відсутність транзакційності (No Rollback):**
   Якщо Аналізатор повертає невалідний JSON або стається виняток під час мутації стану, повідомлення Оповідача вже зафіксовано в `history.json`. Виникає розрив між наративом і станом.
2. **«Lore Loading» (оптимізація читання 43 файлів):**
   У `_read_all_lore()` зчитується 43 файли лору (~38 000 токенів кирилиці) і передається в системний промпт Оповідача. Для моделей рівня Gemini (контекстне вікно 1M+) такий обсяг є цілком комфортним і зберігає глибину ігрового світу та випадкові відсилки/події.
   *Проблема не в розмірі лору, а в дисковому I/O:* сервер відкриває 43 файли з диска щоразу під час кожного ходу замість того, щоб один раз завантажити їх в оперативну пам'ять (RAM-кеш) при старті сервера.
3. **Ручний парсинг JSON:**
   Використання рядкових операцій `find('{')` і `rfind('}')` замість OpenAI `response_format={"type": "json_object"}` або Structured Outputs (`beta.chat.completions.parse`). Це створює ризик падіння, якщо модель згенерує дужку або коментар поза схемою.

## 4. Дорожня карта рефакторингу Backend

### Фаза 1. Швидкі виправлення (Quick Wins & Security)
- [ ] Очистити `test_api.py` від хардкод-ключа, перевірити `.gitignore`.
- [ ] Запровадити Pydantic DTO для `main.py` (`ActionRequest`, `ActionResponse`, `IntentItem`).
- [ ] Кешувати файли лору та промптів у пам'яті (завантажувати 1 раз при старті, а не на кожен крок).
- [ ] Додати транзакційний відкат історії повідомлень при помилці кроку Аналізатора.

### Фаза 2. Модульність та сервіси
- [ ] Розділити `LLMController` на:
  - `PromptService` (управління шаблонами та лором).
  - `NarratorService` (генерація художнього опису).
  - `StateAnalyzerService` (витяг дельти через Structured Outputs).
  - `HistoryService` (збереження та компресія історії).
- [ ] Підключити `response_format={"type": "json_object"}` для запитів Аналізатора.

### Фаза 3. Персистентність та оптимізація пам'яті
- [ ] Додати `session_id` для підтримки незалежних ігрових збережень (папки `data/saves/{session_id}/`).
- [ ] Оптимізувати структуру зберігання контейнерів (усунути конфлікти, коли рюкзак одночасно лежить на підлозі і є верхньорівневим контейнером).
- [ ] *(Опціонально/Експериментально)* Якщо в майбутньому база лору виросте понад 100+ файлів — додати селектор за тегами локацій. Для поточних 43 файлів залишається повне контекстне завантаження.

### Фаза 4. Streaming (SSE / WebSocket)
- [ ] Створити ендпоінт `POST /api/v1/action/stream` з використанням Server-Sent Events (`StreamingResponse`):
  1. Потік токенів Оповідача стрімиться гравцю в реальному часі.
  2. Після завершення наративу у фоні запускається Аналізатор.
  3. Фінальний івент передає оновлений `player_state`.
