## 1. Архітектура: Персонаж (Blueprint) ➔ Кампанії (Campaigns)

- **Character Blueprint (Заготовка персонажа):**
  - Зберігається у `data/characters/{char_id}.json`.
  - Вихідний лист героя: ім'я, біографія, зовнішність, стартові навички, базове екіпірування.
  - Його можна редагувати (змінити опис, навички) або видалити.
- **Кампанії (Campaigns / Чати):**
  - Зберігаються у `data/saves/{session_id}/`.
  - За одним персонажем можна вести **будь-яку кількість паралельних незалежних кампаній**.
  - У кожній кампанії зберігається повна історія повідомлень (`history.json`).
  - Кожна кампанія має статус закріплення (`is_pinned: bool`) та назву.
- **Вступний пост Оповідача (Intro Post):**
  - При створенні нової кампанії бекенд автоматично генерує художній вступ (зав'язку пригоди) на основі передісторії та стартової локації персонажа. Гравець одразу опиняється в живій сцені.
- **Системний шаблон (`_template.json`):**
  - Повністю порожній, захищений від змін. Заборонено використовувати як ігрову кампанію.

## 2. Завдання в роботі (Фаза 2)

### 🧹 2.1. Очищення проєкту від Flet
- [ ] Видалити застарілий `Backend_Python/client.py` та папку `.flet`.
- [ ] Видалити 6 пакетів `flet*` із `Backend_Python/requirements.txt`.

### 👤 2.2. Управління заготовками персонажів (Character Blueprints)
- [ ] Створити теку `data/characters/` для збереження базових листів.
- [ ] `GET /api/v1/characters` — список усіх створених персонажів.
- [ ] `GET /api/v1/characters/{char_id}` — отримати повний базовий стан.
- [ ] `PUT /api/v1/characters/{char_id}` — редагування заготовки героя.
- [ ] `DELETE /api/v1/characters/{char_id}` — видалення персонажа з диска.

### 🧙‍♂️ 2.3. Створення героя з AI (Character Wizard)
- [ ] Системний промпт `data/prompts/character_creator_system.txt`: AI Творець Долі допомагає створити персонажа за лором світу.
- [ ] `POST /api/v1/character/dialog` — інтерактивний крок діалогу з Творцем Долі.
- [ ] `POST /api/v1/character/finalize` — фіналізація konceptu в `PlayerState` та збереження у `data/characters/{char_id}.json`.

### ⚔ 2.4. Менеджмент Кампаній (Campaigns)
- [ ] `GET /api/v1/characters/{char_id}/campaigns` — список кампаній обраного персонажа (з урахуванням `is_pinned`).
- [ ] `POST /api/v1/characters/{char_id}/campaigns` — створення нової кампанії:
  - Копіює стан заготовки персонажа;
  - **Обов'язкова авто-генерація вступного посту:** Оповідач генерує стартовий опис сцени, що записується як перше повідомлення в `history.json`.
- [ ] `PATCH /api/v1/campaigns/{campaign_id}/pin` — закріпити / відкріпити кампанію у списку (`is_pinned`).
- [ ] `DELETE /api/v1/campaigns/{campaign_id}` — видалення кампанії з диска.
- [ ] `GET /api/v1/campaigns/{campaign_id}/history` — отримання **повної історії повідомлень** кампанії для завантаження в чат клієнта.
