## 1. Завдання в роботі (Фаза 3.1)

### ⚡ 1.1. Оптимізація швидкості Аналізатора та роздільний скоринг моделей
- [ ] У `core/services/llm_provider_service.py` розділити критерії ранжування моделей для `story` та для `state`:
  - **Для `story` (Оповідач / Наратив):** пріоритет на максимальну літературність, багатство мови та глибину контексту (Claude Haiku 4.5, Qwen 3.5 Plus, Gemini 3 Flash).
  - **Для `state` (Аналізатор стану):** пріоритет на надшвидкі моделі з бездоганною підтримкою структурованого JSON / Tool Calling (`free-gemini-3.1-flash-lite`, `free-gemini-3-flash-preview`, `free-qwen3.5-flash`), із каскадним переходом (fallback) на важчі моделі лише у разі помилки валідації.
- [ ] Перевірити час відповіді Аналізатора: він повинен складати 0.8–1.5 секунди замість поточних затримок важких літературних моделей.

### 🎙️ 1.2. Ендпоінт голосової транскрипції (Voice-to-Text)
- [ ] Реалізувати ендпоінт `POST /api/v1/voice/transcribe`:
  - Приймає аудіофайл (`multipart/form-data`) у форматах WAV або OGG (запис з мікрофона клієнта).
  - Виконує швидке розпізнавання мови через доступний OpenAI-сумісний Audio Transcription API (наприклад Odirouter, Groq або локальну бібліотеку/сервіс).
  - Повертає розпізнаний текст: `{"text": "розпізнаний текст дії гравця"}`.

### 🔄 1.3. Синхронізація ручних правок прев'ю (Live Sync)
- [ ] Реалізувати ендпоінт `POST /api/v1/character/sync-draft`:
  - Приймає поточний стан `PlayerState`, в якому гравець вручну відредагував окремі текстові поля (наприклад, біографію чи передісторію).
  - ШІ аналізує зміни та узгоджує взаємозалежні характеристики (наприклад, якщо гравець написав про магічний шрам чи навчання у вежі магів — додаються відповідні здібності чи риси).
  - Повертає оновлений та збалансований `PlayerState`.
